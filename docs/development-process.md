# Development Process

## Background

プログラミング未経験の状態から、AI Coding Toolsを利用して開発しています。

ただし、AIが提案したものをそのまま実装する方法は採用していません。

## Working loop

```text
1. 問題を定義
2. 今回の変更範囲を限定
3. 既存構造との衝突を確認
4. AIに実装案・リスク・代替案を出させる
5. 実装
6. テスト
7. 既存機能への影響確認
8. Go / No-Go
```

## AIへの基本ルール

- 自分の提案でも無条件に賛成しない
- 不要な機能追加を避ける
- 既存Phaseを勝手に変更しない
- 変更ファイルを明示する
- テスト結果を報告する
- 未実装部分を明示する
- 問題が未確認なら推測でproduction logicを変更しない

## Why this matters

AIを使うほど実装速度は上がりますが、プロジェクト全体の整合性をAIに任せると、局所最適の変更が積み重なる可能性があります。

そのため、AIは実装パートナーとして使いながら、要件・優先順位・採否・完了条件は人間側で管理しています。
